KPI & Metric Dictionary

What every number on the Overview tab means and exactly how it's calculated.

Opportunity List

  • One row per matched Opportunity (same population as "Total" on Overview: open all‑time + closed in the last 12 months), not aggregated — it uses the same filters and identity scoping as the Overview tab (set filters there; this list respects them without its own copy of the filter bar).
  • Split into four independently sorted, paginated sections by stage: Open (every non‑closed stage except Future Opportunity), Future Opportunity, Closed–Won, and Closed–Lost — the search box above filters all four at once.
  • Product combines NV Product Line and Service Level into one column, separated by • (e.g. "Restock • Standard").
  • Aging = days since created_at (same definition as Deal Aging). Last Stage Duration = days since stage_last_changed_at (falling back to updated_at) — same definition as Stage Bottlenecks.
  • Overdue: the deal is still open and expected_close_date has already passed.
  • Notebook Last Touch: days since the most recent Notebook entry (falling back to created_at if the deal has no Notebook entry at all) — same last‑entry lookup as the Activity panel, computed here for every row (not just open deals).
  • Notebook Content: the AI‑generated summary of the most recent Notebook entry. The CRM only returns this text to the entry's own creator or an admin — for any other entry it comes back blank even though a note exists, because the API key this app runs under isn't that entry's creator.
  • Click a column header to sort by it (click again to reverse); click an Opportunity Name to open that record directly in the CRM.

Data population & methodology

  • "Record Type Indonesia" and "Record Type 12" are the same filter — Indonesia's record type ID in this CRM is 12.
  • Population: every OPEN Indonesia opportunity regardless of age (so no old stale lead is missed), plus any opportunity — open or closed — created in the last 12 months. Indonesia has 72,721 Opportunity records all‑time; fetching every one blew both the platform's request timeout and its memory limit, so closed/won history beyond 12 months isn't included. This population is what "Total" / "opportunities matched" refers to everywhere below unless a metric says otherwise.
  • Data is refreshed by a background job roughly every 15 minutes (a full pull is ~73k records — too slow to run per page load), not sampled and not read off the CRM's own filter UI — that UI's per‑field filters proved unreliable for the Service Level field.
  • "Last Mile – Parcel" and "Last Mile – Document" are excluded except for Raden Roro Inggil Pratiwi's opportunities (a data‑quality rule, not a CRM limitation).
  • Prospecting is a legacy stage value no longer offered in the CRM's own stage filter dropdown. A deal actually sitting in it still counts toward Open Pipeline and every other stage‑grouped panel — it just isn't given its own bar on the Deals by Stage chart specifically.
  • Any record with "UNAUTHORIZED OPPORTUNITY" in its name is excluded from every count as a non‑pipeline test artifact.
  • Open (used throughout as "open deals" / "open + future") means every stage except Closed–Won and Closed–Lost — this includes Future Opportunity.
  • Filter bar (Salesperson / Manager / NV Product Line / Service Level, top of the Overview tab): multi‑select, applies to the entire dashboard — every stat card, chart, and table on this page recomputes against the filtered population, not just the panels that already broke deals down by that field. Selections within one filter are OR'd (any match), across different filters they're AND'd (must match all). Manager filters by each deal's owner's Manager in the team roster; a deal whose owner isn't in the roster won't match any Manager filter. Service Level is a multi‑select field on the deal itself, so it matches if the deal has any of the selected levels. Task Activity respects the Salesperson/Manager filters but ignores Product Line/Service Level (Tasks aren't tagged with either).
  • Identity‑scoped viewing: if the person who's logged in (via the platform's Google SSO, identified by an unspoofable X-Forwarded-Email header) is mapped to a name in the team roster, the whole dashboard is pre‑restricted to what they're allowed to see — a Salesperson sees only their own pipeline; a Manager or Sales Head sees their full downstream team (Sales Head covers every rep under every manager reporting to them, not just direct reports). This is a real boundary, not just a default: the filter bar can only narrow further within that scope, never escape it. A "Viewing as …" chip next to the title shows when this is active. Anyone not in the email‑to‑roster mapping (or if SSO isn't the access method) sees the full unrestricted dashboard.

Action Items

  • Lives on its own Action Items sidebar tab, not Overview — it uses whatever filters are set on Overview (Salesperson/Manager/etc.), so set those first.
  • Who sees it: only an identity‑scoped viewer (a mapped Salesperson or Manager/Sales Head), or an unmapped/admin viewer who has deliberately filtered the dashboard down to a specific Salesperson or Manager. An unmapped viewer with no such filter sees a placeholder instead — it's personalized, not a general summary.
  • Every category below only considers OPEN, non‑Future‑Opportunity deals (Future Opportunity is deliberately parked, not actively worked) within whatever scope applies (your own pipeline, or your team's).
  • Overdue: expected_close_date has passed and the deal is still open. Sorted by days in the current stage, worst first.
  • Stalled in Stage: stage_last_changed_at (falling back to updated_at) is 30+ days old — the same threshold Stage Bottlenecks/Stage × Ageing use for their "30d+" tier.
  • Notebook Needs Updating: last Notebook touch (or created_at if none) is 14+ days old — the same threshold the Activity panel's "14‑30d" tier starts at.
  • Tasks Awaiting Action: open Tasks (Not Started / In Progress) that aren't "Active" by the exact same rule the Activity panel's Task side uses (touched within 7 days AND not overdue).
  • Viewing a single person's own pipeline shows up to 8 example deals per category (worst first), with the true total in the summary sentence. Viewing a Manager/Sales Head's team instead shows a per‑rep breakdown — each rep's name with their own matching deals/tasks listed underneath, hyperlinked to CRM.
  • Monthly Pace: every rep in scope against the same 10‑opportunity monthly target as Created Opportunities by Manager & Salesperson, sorted most‑behind‑target first — includes reps with 0 created this month.

Top summary cards

  • Created This Month / vs last month: count of opportunities whose created_at falls in the current / previous calendar month and whose type is Acquisition or Cross‑Selling — new business only, excluding Pricing/Up‑Selling/Regain/Others opportunities raised against an existing account. The Created Opportunities by Manager & Salesperson table below uses the same Type filter.
  • Open Pipeline: count of all OPEN deals (open_active + Future Opportunity). Not Type‑filtered.
  • CRM Updated %: the final combined Activity KPI — see "Activity" below for the full definition.
  • Closed–Won / Closed–Lost (This Month) / vs last month: count of deals whose stage is Closed–Won / Closed–Lost and whose stage_last_changed_at (falling back to updated_at) falls in the current / previous month — i.e. deals that actually closed this month, not deals merely created this month. Not Type‑filtered.
  • Pipeline Conversion: Closed–Won this month ÷ unique deals in (Created this month ∪ Open Pipeline ∪ Closed–Won this month ∪ Closed–Lost this month). The denominator is every distinct deal "in play" this month — newly created, still open, or resolved either way — deduplicated by id, so a deal created and closed within the same month is only counted once, not once per bucket.
  • Potential Rev / Mth: sum of total_potential_revenue_mth (and, for the sub‑label, committed_revenue_mth) across the full population.

Deals by Stage & Pipeline Composition

  • Pipeline Composition (donut): the full population split into four outcome buckets — Active pipeline, Future opportunity, Closed–Won, Closed–Lost — as a share of the total.
  • Deals by Stage (bars below the donut): count of deals currently sitting in each stage, ordered by the sales process sequence (Active pipeline), then Closed & parked (Closed–Won, Closed–Lost, Future Opportunity).
  • The percentage next to each section header (Active pipeline, Closed & parked) is that section's share of the total — it matches the corresponding donut bucket(s) above (Closed & parked = Future opportunity + Closed–Won + Closed–Lost combined).

Product Line, Service Level, Top Salesperson & Ageing

  • All four consider OPEN deals only (open + Future Opportunity) — closed–won/lost are excluded, unlike Deals by Stage above.
  • Deals by NV Product Line: count of open deals per nv_product_line value.
  • Deals by Service Level: service_level is a multi‑select field, so one deal can add to more than one bar — percentages are share‑of‑open‑pipeline per tag, not a partition. "Blank" counts deals with no Service Level tag at all.
  • Top Salesperson: open deal count per owner_name, ranked descending. Each rep's bar is itself split into ageing segments — for every OPEN deal, days = today − created_at (purely creation age, no Notebook fallback), bucketed into 0‑7d, 7‑15d, 15‑30d, 30d+ (see the color legend above the chart) — so a rep with a long bar mostly in the 30d+ color has a lot of ageing pipeline, not just a lot of pipeline.

Activity

  • Two independent freshness signals feed one final KPI: Notebook (a note logged on the Opportunity) and Tasks (CRM Task records) — a rep can be current on one and stale on the other.
  • Notebook: entries are fetched separately from Opportunities (GET /notebook/entries?object_type=Opportunity, paginated) and reduced to the most recent entry's created_at per opportunity id. For every OPEN deal, last_touch = that Notebook date, or created_at if the deal has no Notebook entry at all (never touched ≠ recently touched); days = today − last_touch, bucketed into 4 tiers: < 7d (green), 7‑14d (yellow), 14‑30d (orange), 30d+ (red / not touched). "Notebook touched in last 7 days" = count in the <7d tier ÷ total open deals.
  • Tasks: population is CRM Task records (not Opportunities) with status in Not Started or In Progress — Completed and Deferred are excluded entirely. Task is a global object with no country field, so it's fetched pre‑filtered server‑side to just the owner_ids in the Indonesia team roster (a rep only owns their own country's work), not a full global pull. A task counts as Active when both hold: (1) last_touch (=updated_at, falling back to created_at if never edited since logged) is within the last 7 days, AND (2) it is not overdue (due_date is blank, or today or later). "Tasks active in last 7 days" = Active task count ÷ total open task count.
  • CRM Updated % (the final KPI, also shown as a top summary card): Notebook and Task counts are summed, not averaged — (Notebook <7d count + Task Active count) ÷ (total open deals + total open Tasks). Summing means a rep with many open deals but few Tasks isn't equally weighted between the two signals; it's one pooled ratio, not an average of two percentages.
  • By salesperson table: one row per rep. CRM Updated (%) is that rep's own version of the final KPI (their Notebook <7d + Task Active, over their own open deals + open Tasks), followed by the Notebook detail (Updated % plus its 7‑14d/14‑30d/30d+ counts and Total — the <7d count is omitted since the % column already shows it) and the Task detail (Updated %, Updated Task count, Open Tasks). Sorted best‑first on CRM Updated (%); a rep with no open deals but open Tasks (or vice versa) still gets a row, with "–" on the side that doesn't apply. Reps with no owner_id on file in the team roster can't be queried for Tasks at all — their Task columns show "–" and their CRM Updated (%) falls back to Notebook‑only (not directly comparable to reps with both signals); they're named in the caption below the table.

Stage Bottlenecks & Stage × Ageing

  • Both use stage_last_changed_at (falling back to created_at) — i.e. how long a deal has sat in its current stage, not since it was created.
  • Stage Bottlenecks: average days‑in‑current‑stage per stage, across OPEN deals only, longest first.
  • Stage × Ageing: for each stage, the same day buckets used throughout (0‑7d/7‑15d/15‑30d/30d+), shown as a composition bar — Share mode normalizes every stage's bar to 100%; Count mode scales bar width by the stage's total deal count so stages can be compared by volume too.
  • Avg lead time to Closed–Won (below the Stage Bottlenecks table): for every Closed–Won deal, days = stage_last_changed_at (or updated_at) − created_at. The CRM has no separate "entered New stage" timestamp, so created_at is used as a proxy for it — the same approximation the ageing buckets rely on.

Pipeline Strength (Forecast)

  • Population: OPEN deals with an expected_close_date (deals with none are excluded and counted in the panel's caption).
  • Overdue: expected_close_date < today. Everything else is bucketed by the month of expected_close_date, starting at the current month and continuing through however far into the future the data goes (no fixed 3‑month cap).
  • Each bar is stacked by stage and labeled with count + potential revenue, so it's visible whether deals due to close soon are actually in a late stage (Agreed to Ship / Ready to Ship) or an unrealistically early one.
  • Bar height uses a square‑root scale (not linear) so low‑count months next to a high‑count one don't flatten to an invisible sliver — the printed count above each bar is always the real number.

Created Opportunities by Manager & Salesperson

  • Population: opportunities (open + closed) whose type is Acquisition or Cross‑Selling (same new‑business filter as the "Created This Month" card), grouped by the month of created_at, for the current month and the two before it.
  • By Manager: each opportunity's owner_name is looked up in a curated team roster (Active reps only — see backend/team_roster.json) to find that rep's Manager; owners not found in the roster are grouped as "Unmapped" (named in the panel's caption).
  • By Salesperson: one row per Active rep in scope, including reps who created nothing in this window (shown as 0) — unlike the other tables on this dashboard, this one isn't built only from matched deals, so a quiet rep is still visible. "In scope" respects the top filter bar: no Salesperson/Manager filter shows every Active rep; filtering to a Manager narrows this to just their reports; filtering to specific Salesperson(s) narrows it to just them.
  • Target: each rep is expected to create 10 opportunities a month; a manager's target is 10 × their headcount (reps reporting to them, per the roster).
  • Current month column: shows count/target plus a bar filled to min(count ÷ target, 100%), colored red (<50%), orange (50‑74%), yellow (75‑99%), or green (≥100%) — since the month is still in progress, this reads as "progress so far", not a final score.
  • Earlier months: show the count plus (count ÷ target) as a percentage — a finished month's actual achievement against the same target. A ▲ green triangle means that month's count is higher than the month before it; ▼ red means lower (the very first month shown has no prior month to compare against, so no triangle).
